# BUG-005 – Chốt chặn NFR08 vượt được (`/<db>/x_test`, `?host=`, chạy vitest từ gốc repo)
- Agent: devops · Trạng thái: REVIEW · Ngày: 2026-11-01
- FR/NFR: NFR08 · Làm chung vòng sửa 3 của T201 – chi tiết, quyết định thiết kế, bằng chứng đầy đủ: `reports/T201.md` mục "Vòng sửa 3"

## Nguyên nhân
- (a), (b): `checkTestDbEnv` tự phân tích chuỗi URL khác Prisma – lấy cả `nckh_dev_qa/x_test` làm tên DB (Prisma dùng đoạn đầu), bỏ qua tham số `host` (Prisma kết nối host đó).
- (c): chốt chặn chỉ nằm ở `apps/api/vitest.config.js`; chạy vitest từ gốc repo không có config nào → không chốt chặn, `resetData()` TRUNCATE DB đang trỏ tới.
- Chung: mọi lớp bảo vệ chỉ là phân tích chuỗi, không lớp nào hỏi chính DB.

## Đã sửa
1. `apps/api/scripts/test-db-guard.js`: tên DB phải khớp `^\w+_test$` (một đoạn); tham số URL theo danh sách trắng (`host`, `Host`, `hostaddr`, tham số lạ → từ chối).
2. Kiểm mức DB `DB_LEVEL_CHECK_SQL` (`current_database()` dạng `*_test`, `inet_server_addr()` null/loopback/dải riêng, sai → `RAISE EXCEPTION` tiếng Việt), chạy trên đúng kết nối sẽ phá dữ liệu:
   - `scripts/reset-test-db.js`: `prisma db execute --stdin --url` cho mọi URL của schema, trước `db push`/`migrate reset`;
   - `tests/db.js` `resetData`: trước TRUNCATE ("Từ chối dọn dữ liệu: …");
   - `tests/global-setup.js`: sau `SELECT 1` ("Từ chối chạy test: …").
3. `vitest.config.js` gốc mới: `test.projects: ['packages/*', 'apps/*']` – chạy từ gốc dùng config của từng workspace. `packages/shared/vitest.config.js` rỗng để vitest trong shared không tìm ngược lên config gốc.
4. `tests/T201-db-helpers.test.js`: +1 test phân tích URL mới.

Test của QA (`T201-qa-guard-bypass.test.js`, `T201-qa-isolation.test.js`) không sửa. MINOR TC-NFR08-02 (khớp lỏng) là test của QA – chỉ ghi nhận, reviewer quyết.
