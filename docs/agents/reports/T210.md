## Đã làm
- `POST /api/topics/:id/actions` (STUDENT, LECTURER; limiter 30/15 phút/user) với 4 nhánh FR16: REQUEST_ADVISOR, ACCEPT_ADVISING, DECLINE_ADVISING, WITHDRAW_ADVISOR_REQUEST. Thứ tự: tải -> quyền xem (403, trước trạng thái) -> `checkTransition` -> version -> điều kiện riêng -> `applyTransition`.
- `applyTransition` chạy qua `withLockTx` (lock_timeout đặt trước `updateMany`).
- REQUEST_ADVISOR: trong `[regOpenAt, regCloseAt)` (409 `REGISTRATION_CLOSED`), `topicSubmitSchema` (400 `TOPIC_INCOMPLETE` + details), `lecturerId` hợp lệ (400 tại `lecturerId`). Trong tx theo §5.5: đọc lại thành viên, `GROUP_TOO_SMALL`, khóa User mọi thành viên (id tăng dần, NO KEY UPDATE), đếm từng SV bằng câu riêng -> `STUDENT_TOPIC_LIMIT {codes}`, tạo AdvisorRequest, lời mời PENDING -> WITHDRAWN (MINOR 1 T208).
- ACCEPT_ADVISING: khóa User GV, đếm Advising hiện hành (cùng đợt, đề tài hoạt động) < `maxTopicsPerLecturer` (409 `LECTURER_QUOTA_EXCEEDED`), request -> ACCEPTED, tạo Advising. DECLINE: request -> DECLINED + reason. WITHDRAW: -> WITHDRAWN. Cập nhật request có điều kiện PENDING.
- `GET /api/advisor-requests` (LECTURER/STUDENT/STAFF, `createdAt ASC, id ASC`, `pendingDays`), `GET /api/lecturers?roundId` (activeTopicCount, maxTopics, isFull, không lộ email).
- AuditLog `ADVISOR_REQUEST_CREATE/ACCEPT/DECLINE/WITHDRAW` và StatusHistory cùng transaction.
